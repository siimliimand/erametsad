# Erametsad — Auction Platform Flow Document

> Source-verified against the codebase on 2026-09-14. Candidate repo location if promoted: `docs/auction-flows.md`.
> All paths are relative to the repo root; `platform/` abbreviates `apps/platform/`.

---

## 1. System context

Monorepo (`apps/platform` + `packages/ui|types|emails|config`). The platform is a single Next.js app on Cloudflare Workers (OpenNext) serving three hosts:

| Host | Audience |
|---|---|
| Marketing site | public, live ticker + lead forms |
| `oksjonid.erametsad.ee` (`(portal)` route group) | buyers/sellers — auction portal |
| `admin.erametsad.ee` (`(admin)` route group) | staff backend, 13 role-gated modules |

Infrastructure:

- **D1 (SQLite, Drizzle)** — 39 tables: `users`, `profiles`, `auctions`, `bids`, `autobidders`, `auction_rights`, `rights_requests`, `contracts`, `contract_templates`, `notifications`, `notification_templates`, `audit_entries` (hash-chained), `settings` (singleton), CMS + geo tables.
- **Durable Objects** — `AuctionDO` (one per auction: bid serialization, alarms, anti-snipe, end transitions, SSE event hub) and `RateLimiterDO`.
- **Queue** `erametsad-jobs` — notification fan-out.
- **SSE** — `GET /api/v1/auctions/stream` (public), `GET /api/v1/my/stream` (authenticated).

## 2. Core domain model

**Object types** (`objectType`, `platform/src/lib/data/schema`):

- `raieoigus` — cutting right (requires logging volume)
- `kinnistu` — forest property
- `kiire` — quick auction (24–72 h)
- `pakett` — package (multiple cadastral units)
- `pollumaa` — farmland

**Auction format** (`type`):

- `open` — English ascending auction with bid step + anti-snipe extension.
- `sealed` — "Suletud pimepakkumine": blind bids, revision cap, decryption ceremony after end.

**Status chain** (`platform/src/lib/auction/status-transitions.ts`) — immutable, one step per update, each status stamps its timestamp column:

```
draft → scheduled → active → ended → appraised | unsold
appraised → contract → completed → archived
unsold → completed → archived
```

**Bids** (append-only): `leading → outbid`, `pending_approval` (alapakkumine under-start request), `rejected`, `won`/`lost` (sealed). Sealed rows store `amount_cents = 0` at rest — the real amount lives inside an encrypted envelope (`identity_snapshot`).

Money is stored in cents (`minBidCents`, `bidStepCents`, `reservePriceCents`, `amountCents`), displayed in EUR.

## 3. Auctions listing page (portal `/`)

File: `platform/src/app/(portal)/page.tsx` (server component, `force-dynamic`).

1. **Tabs** (`ListingTabs`) — one tab per object type; live counts from `activeStatsByObjectType`.
2. **Filters** — all URL params (shareable via `buildListingHref`): county, parish, species, logging type, cut-deadline year, area/volume/price ranges, free-text `q`, sort/order, `page`.
3. **Query** — `listAuctions` (`platform/src/lib/auction/queries.ts`): active auctions only, server-side pagination; `listAuctionMapPoints` feeds the map view (`?view=kart`).
4. **Live updates** — the page mounts `AuctionStreamProvider` (`(portal)/_lib/use-auction-stream.ts`), an SSE client for `/api/v1/auctions/stream` (reconnect backoff 1 s → 30 s). Events: `bid:created`, `auction:extended`, `auction:ended`, `auction:published`. `LiveListing` re-fetches on events. Public frames carry **no amounts** — guests cannot recover bid values from raw frames.
5. **Lot cards** (`PortalLotCard`) + centered pagination; empty state suggests subscribing to notifications (`auction-subscriptions`).

## 4. Auction detail page (portal `/oksjon/[id]`)

File: `platform/src/app/(portal)/oksjon/[id]/page.tsx`.

Server render (`force-dynamic`):

- `getAuctionDossier` — full lot model plus viewer participation flags (`hasBid`, `isLeading`, `hasAutobidder`, `hasPendingUnderStart`).
- `getAuctionBids` — role-shaped bid list (open auctions only; sealed pages show a count).
- Framework-contract pre-check `hasSignedRaamleping` (mirrors the API gate; the API stays the final arbiter).
- Own autobidder row lookup → prefill "Uuenda/Eemalda".

Layout — main column (gallery, description, dossier table, package table, Estonia map, documents, bid list with anchor tabs) + sticky side rail:

- **Open auction rail**: `LiveCountdown` (server-now drift correction, design D4) + `LiveBidPanel` → `BidPanel` with `BidConfirmModal`, `AlapakkumineToggle` (under-start, only if Settings enable it), `AutobidderControl`, `OutbidBanner`, `GuestGateModal` (login gate), anti-snipe hint.
- **Sealed rail**: `SealedBidPanel` — own bids, revision cap, identity prefill, outcome after the ceremony; others see only the bid count.
- **Ended rail**: `EndedPanel` with final price or "Jäi müümata" + similar-lots link.
- **Seller contact** via alias address `mt…@oksjonid.erametsad.ee`.

`oksjon/esivaade/[token]` — stateless HMAC guest preview (24 h) of a **draft/scheduled** lot for reviewers before publish.

## 5. Bid lifecycle (open auction) — the engine

Submission: `POST /api/v1/bids/create` (`platform/src/app/api/v1/bids/create/route.ts`) with `auctionId`, `amount`, `type`, optional `idempotencyKey` + `identitySnapshot`.

1. **Auth** — `access_token` cookie verified (JWT).
2. **AuctionDO admission** — stub fetched by `idFromName(auctionId)`; the DO's `admissionChain` promise serializes every bid per auction (replaces the deleted Postgres `SELECT … FOR UPDATE` row lock).
3. **`admitBid` checks** (`platform/src/do/auction.ts`, the single admission path):
   1. idempotency replay from DO storage (retried requests get the original answer, no re-write);
   2. user exists, not suspended;
   3. auction `active` and `endsAt` in the future — **the D1 row decides, not the hot cache**;
   4. `auction-rights` entry for this objectType, not revoked (403 without it);
   5. Settings: `alapakkumineEnabled`, `requireFrameworkContract` flag;
   6. amount ≥ `minBid` — otherwise only legal as an alapakkumine request;
   7. step check: amount ≥ leader + `bidStepCents`;
   8. framework-contract gate (open only): signed `contracts` row against the active `framework` template, else coded 403 `framework_contract_required` → client redirects to `/lepingud/raamleping`;
   9. cross-writer idempotency (unique index, 409);
   10. sealed only: revision budget `1 + sealedRevisionCap` (coded 400 `revision_cap_exceeded`).
4. **Writes — one atomic D1 batch**: insert bid (`leading`, or `pending_approval` for under-start), demote previous leader (`leading → outbid`, status-guarded), audit `bid_placed`, `ends_at` touch when anti-snipe fires.
5. **Anti-snipe** (`platform/src/lib/bidding/anti-snipe.ts` semantics, ported into the DO): a bid inside the window (default 5 min, clamped 1–30, per-auction toggle) extends `endsAt` by one window; the DO alarm re-arms. Sealed auctions never extend.
6. **Autobidders** — after a *manual* leading bid, `evaluateAutobidders` admits the strongest eligible autobidder by re-entering `admitBid` (loop; an autobid never re-triggers evaluation).
7. **Broadcasts** — after commit: DO SSE `bid:created` (+ `auction:extended`); route mirrors to legacy hubs: `emitBidCreated`, `pushOutbid` (personal my-stream), `emitAuctionExtended`.
8. **Notifications** — `bid.created` / `outbid` DomainEvents emitted post-commit only, fanned out via queue through versioned e-mail/SMS templates.

**Alapakkumine (under-start)**: lands as `pending_approval`, never takes the lead; one pending at a time (previous auto-rejected). Seller/admin approve or reject — `my-auctions/[id]/underbids/[bidId]/approve|reject` and admin detail actions (`approveAlapakkumine`/`rejectAlapakkumine`) → approval makes it `leading`.

**Fallback**: when the `AUCTION` binding is absent (plain dev), the route falls back to in-process `placeBid` (`platform/src/lib/bidding/place-bid.ts`) with the same check chain, then `checkAntiSnipe` + `evaluateAutobidders` in-process.

## 6. End of auction

- `AuctionDO.alarm()` fires at `endsAt`; a **cron sweep** POSTs `/:auctionId/due` as a safety net — both run the same serialized `alarmTick` **inside the DO**; the client never ends auctions.
- `active → ended` (audit `auction_ended`).
  - **Sealed**: stops at `ended`, flags `sealedOpeningPending`, notifies the seller.
  - **Open**: outcome phase — leader exists **and** reserve met → `appraised` (winning bid, final price, winner + seller notifications); otherwise `unsold` (reserve-not-met notifications).
- Broadcasts `auction:ended`; countdowns and the listing react via SSE. Every SQL statement is status-guarded so a retried alarm can't double-fire.

## 7. Buyer usage flow (end to end)

1. **Register** (`(portal)/register`): e-ID identification (Smart-ID / Mobile-ID / ID-card via `/api/v1/auth/{smartid,mobileid,idcard}/*`) → email + `isikukood` → profile type (private, or company via registry lookup; company staff file access requests) → consents recorded in `consent_log`.
2. **Bidding rights**: request per object type (`POST /api/v1/my/rights-requests`, one pending per type) → admin grants → `auction_rights` row. Bidding without a right = 403.
3. **Framework contract** (`/lepingud/raamleping`): `prepare` renders the active template → `sign` within a **15-minute session** (SHA-256 `contentHash`); required before open-auction bids (Settings flag).
4. **Browse & study**: listing → lot detail → dossier, documents (signed links), map, seller alias email; optionally subscribe to lot/auction notifications.
5. **Bid**: manual (confirm modal) or autobidder ceiling; optional under-start request; outbid → personal SSE push + notification.
6. **Win**: `won` notification → auction contract (`/lepingud/oksjonileping`) prepare → sign (15-min session) → status `contract` → `completed`. Fee from Settings (`SUCCESS_FEE_PERCENT` / per-lot override, VAT-aware price summary).
7. **Lose / ended**: ended notification; sealed outcome arrives only after the opening ceremony. Past lots surface in the public archive (`/ajalugu`) and the user area `/user` (bids, objects, notifications, profile; GDPR export/delete under `my/*`).

## 8. How a new auction is created (admin)

Entry: Admin → Oksjonid (`/admin/auctions`: filterable list, CSV export, bulk schedule, row actions duplicate / re-list / archive / end manually) → **"Uus oksjon"** (`/admin/auctions/new`).

### 8.1 Seven-step wizard

(`_components/AuctionWizard.tsx`, registry in `steps.tsx`; step 6 hidden unless `objectType=pakett`)

| # | Step | Content |
|---|---|---|
| 1 | Tüüp ja mehaanika | objectType, open/sealed, quick-auction flag (auto 24–72 h defaults), anti-snipe toggle + minutes, startsAt/endsAt (Tallinn wall time → UTC ISO) |
| 2 | Asukoht | county/parish, address, lat/lng, Kataster/Metsaregister links |
| 3 | Maa ja mets | cadastres (`#####:###:####`), registry numbers, compartments, species, logging types, area ha, volume m³, forest notifications, deadlines, approval codes |
| 4 | Hind | minBid, bidStep, **reserve (write-only — never rendered back, only a `hasReserve` fact)**, fee override (permission `auctions:fee-override`) |
| 5 | Sisu | public/internal/secondary description, specialist, alias email, media upload (`POST /api/v1/media`), tagged PDF files |
| 6 | Pakett | package table rows (cadastre, registry no, county, area, min bid) |
| 7 | Ülevaade | review + gate summary |

### 8.2 Autosave

Idle/step-change/blur triggers `autosaveAuctionDraftAction` — content-only, optimistic concurrency against `updatedAt` (conflict banner + explicit takeover), mechanics of scheduled/active lots refused, `auction.autosave` audit with field names only. The client also keeps a localStorage draft with a restore prompt; the form submit remains the durable save.

### 8.3 Submit intents

Footer buttons → server actions in `(admin)/_actions/auctions.ts`: `Mustand` (draft) / `Ajasta` (schedule) / `Avalda` (publish).

`createAuctionAction` pipeline:

1. `requireAdminRepositories` (role/session), parse intent.
2. Wizard posts the full state as JSON `payload` (legacy flat form keys also accepted) → zod `auctionInputSchema` → `applyQuickAuctionDefaults` → `toAuctionWriteData` (EUR → cents).
3. Specialist scoping: specialists always own their lots; assigning someone else needs `auctions:reassign-specialist`.
4. Unique `slug` (random suffix on collision) + generated alias email.
5. Create with `status: 'draft'` → audit `auction.create` (reserve value never audited — only the fact it's set; design D5/D7).
6. If intent ≠ draft → `applyWizardIntent` runs the gates and walks the chain; errors land on the draft's editor with data preserved.

### 8.4 Publish gates

(`collectPublishGateFailures` + `collectPublishReadinessFailures` in `_lib/auction-schema.ts`)

- *Blocking*: mechanics set; `endsAt > startsAt` (≥ 1 h, ≤ 90 days; quick auction 24–72 h); reserve required on quick auctions; minBid ≥ 0; county+parish chosen; ≥ 1 cadastre; volume required for `raieoigus`; package rows complete.
- *Warnings* (travel in the audit entry, don't block): missing area, missing hero image.
- *Readiness*: specialist assigned, start ≥ 10 min in the future, area present.

### 8.5 Status walk

`draft → scheduled` (if start in future) `→ active`; `publishAuctionRow` walks both steps, stamps `scheduledAt`/`activatedAt`, audits `auction.schedule`/`auction.publish`, and tells the DO to re-hydrate + broadcast `auction:published`.

### 8.6 Lifecycle actions

- **Edit**: mechanics (type, times, min bid, step, objectType, quick flag) locked while `scheduled|active`; admin/superadmin can override with an audited `mechanicsOverride`. Partial-update semantics — keys absent from the payload never wipe stored values.
- **Manual end** (`EndAuctionModal`): reason ≥ 5 chars + outcome (declare winner | unsold); anti-snipe re-check refuses an end while the newest bid sits inside the window; walks `active → ended → appraised|unsold`.
- **Duplicate / re-list**: clone content + mechanics into a fresh draft, lifecycle fields reset; re-list allowed from `ended|unsold`.
- **Archive**: only from `completed` (an unsold lot walks `unsold → completed → archived`); typed reason, audited.
- **Detail page** extras: publish, delete draft, generate contract, alapakkumine approve/reject, alias regenerate, guest-preview link.

## 9. Sealed-auction flow

1. **Submission** (`sealed-admission.ts`): revision budget `1 + cap` (Settings, default 3); each bid stores an encrypted envelope `{amount, identitySnapshot}` with `amount_cents = 0` at rest; everyone except the bidder sees only the bid count.
2. **End**: status `ended` + `sealedOpeningPending`; seller notified.
3. **Opening ceremony** (`/admin/auctions/[id]/ceremony`, API `open-sealed` / `approve-sealed` / `confirm-winner`; `sealed-opening.ts`): `startOpeningSession` decrypts → live audit strip over the DO SSE feed → reveal records (audited) → `approveOpeningSession` → `confirmWinner` sets `appraised` (or void → unsold). Bidders' rows become `won`/`lost`, surfaced in their SealedBidPanel.

## 10. Realtime & notifications

- `AuctionDO` subscribes fan-out URLs and POSTs each event to the bridge `POST /api/v1/internal/auction-events/[subscriptionId]`, which feeds the in-memory SSE hubs (public auction stream + personal my-stream).
- Notifications are durable rows created inside the end/outbid batches, then fanned out through the `erametsad-jobs` queue using versioned e-mail/SMS templates (admin Seaded can edit versions, test-send, count SMS segments).

## 11. Safeguards and edge cases

- **Serialization**: AuctionDO single-threaded admission; D1 row always authoritative over the DO hot cache.
- **Timing**: server-authoritative clocks; alarm + cron sweep; status-guarded SQL makes retries idempotent.
- **Confidentiality**: no amounts in public SSE frames; reserve is write-only; sealed amounts encrypted; identity reveal is audited; audit entries are hash-chained with `ip_hash`/session context; secrets never enter audit payloads.
- **Idempotency** at two layers (DO storage replay + D1 unique index) so network retries never double-bid.
- **Governance**: role matrix from `permissions.ts` (13 modules); specialists scoped to own lots; `settings:write` superadmin-only; maintenance mode 503s portal pages while admin/login stay reachable.
